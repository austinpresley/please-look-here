## Live magnification

Use a separate capture/loupe object owned by `OverlayController`. Connect explicit menu/control actions and an optional shortcut through the existing presentation-command plumbing. Keep it independent of the selected hand. Reuse `ScreenCapture` permission helpers, but **do not reuse its screenshot filter**: screenshots deliberately retain the annotation overlay. Magnification must exclude every app window, including overlay, ink, toolbar, radial, settings and loupe. Resolve our `SCRunningApplication` by PID and use `SCContentFilter(display:excludingApplications:exceptingWindows: [])`; fail closed if our app cannot be identified. App exclusion also covers later-created app windows. Sources: [local screenshot policy](../../Sources/TinyHand/ScreenCapture.swift), [local controller](../../Sources/TinyHand/OverlayController.swift), [Apple filter semantics](https://developer.apple.com/documentation/screencapturekit/sccontentfilter/init(display:excludingapplications:exceptingwindows:)), [Apple's feedback-avoidance explanation](https://developer.apple.com/videos/play/wwdc2022/10156/).

QuiteHandy's reusable pieces are `Magnifier.layout`, `ensureStream`, `startStream`, `stopStream`, `reset` and its complete-frame/IOSurface output handler. Adapt the capture and circular crop, leaving its flashlight, branding, adjustment gestures and animated badges out of this integration. Its asynchronous `SCShareableContent` callback can reach `startStream` after reset or a display switch; stream-identity checks on frame callbacks do not close that startup race. Source: [pinned Magnifier.swift](https://github.com/esreverse/quitehandy/blob/121d9d4edd12a05e8bdc46fc7adf0eae0420fd9c/Sources/QuiteHandy/Magnifier.swift#L498).

Recommended lifecycle:

- One active display stream, serial sample queue, BGRA, `showsCursor = false`, `capturesAudio = false`, explicit `queueDepth = 3`, initially 30 fps. Retain the current frame and at most one pending replacement. Coalesce main-thread delivery, release replaced surfaces and reuse conversion resources if using CGImage instead of IOSurface. Apple documents the surface-pool/latency tradeoff and a maximum queue depth of eight. Sources: [queueDepth](https://developer.apple.com/documentation/screencapturekit/scstreamconfiguration/queuedepth), [frame interval](https://developer.apple.com/documentation/screencapturekit/scstreamconfiguration/minimumframeinterval), [surface lifetime](https://developer.apple.com/videos/play/wwdc2022/10155/).
- Increment a session generation on every start/stop/display change. Check it after every await, before installing a stream and before publishing a frame. Stop a stale stream even if its start completed late. Bound startup/first-frame waiting, for example four seconds like the local screenshot fallback, and bound retries after failure. An unchanged desktop may legitimately supply no new complete frame, so inactivity after a valid frame is not by itself a failure.
- Stop and clear retained contents on off, deactivate, sleep/lock, capture failure, permission loss or display removal. Suspend when app controls/text/capture take ownership. Prefer immediate stop when closed; if retaining the donor's three-second grace, use an independently scheduled cancellable stop, not a pointer tick that the idle optimization may stop. Serialize stop/start so display changes do not accumulate streams. Sources: [local cancellation/context boundaries](../../Sources/TinyHand/OverlayController.swift), [donor reset/three-second policy](https://github.com/esreverse/quitehandy/blob/121d9d4edd12a05e8bdc46fc7adf0eae0420fd9c/Sources/QuiteHandy/Magnifier.swift), [Apple start](https://developer.apple.com/documentation/screencapturekit/scstream/startcapture(completionhandler:)), [Apple stop](https://developer.apple.com/documentation/screencapturekit/scstream/stopcapture(completionhandler:)).

Keep permission requests in a clickable app/settings context. Do not prompt from a captured press or retry every frame. A denied or failed capture should leave the normal pointer usable and offer the existing Screen Recording settings route. Apple's sample notes that permission grant can require app restart. [Permission helpers](../../Sources/TinyHand/ScreenCapture.swift), [Apple sample](https://developer.apple.com/documentation/screencapturekit/capturing-screen-content-in-macos).

### Scaling and coordinates

Capture the full cursor display first and crop the layer locally. This avoids an asynchronous configuration update per pointer movement. Match `NSScreenNumber` to `SCDisplay.displayID`, never array index. On macOS 14+, output pixel dimensions are `ceil(filter.contentRect.size * filter.pointPixelScale)`; on 13 use the matching `screen.frame.size * screen.backingScaleFactor`, as the local screenshot helper does. Do not mix another screen's scale into this calculation. [Apple contentRect](https://developer.apple.com/documentation/screencapturekit/sccontentfilter/contentrect), [pointPixelScale](https://developer.apple.com/documentation/screencapturekit/sccontentfilter/pointpixelscale), [local fallback](../../Sources/TinyHand/ScreenCapture.swift).

For an unpadded full-display buffer, let `F` be that display's AppKit frame, `p = mouse - F.origin`, lens diameter `D` in points and zoom `z > 1`. The donor's bottom-left layer crop is:

```text
w = min(1, D / (z * F.width));   h = min(1, D / (z * F.height))
u = clamp(p.x / F.width  - w/2, 0, 1-w)
v = clamp(p.y / F.height - h/2, 0, 1-h)
contentsRect = (u, v, w, h)
```

This formula already handles negative display origins and mixed backing scales. Preserve the lens aspect ratio if its sample area exceeds a small display; independently clamping both dimensions can stretch the result. For a top-left CPU image crop, use `x = u*pixelWidth`, `y = (1-v-h)*pixelHeight`, then outward-round and intersect with buffer bounds. These are coordinate conversions derived from [donor layout](https://github.com/esreverse/quitehandy/blob/121d9d4edd12a05e8bdc46fc7adf0eae0420fd9c/Sources/QuiteHandy/Magnifier.swift#L412), not mixed-display runtime verification.

If later using `sourceRect`, define bottom-left local `sample = (u*F.width, v*F.height, w*F.width, h*F.height)`. Its capture coordinates are display-local logical points: `x = sample.minX`, `y = F.height - sample.maxY`. It is not a global AppKit rect or backing-pixel rect. Stream updates must be serialized/coalesced. The full-display crop above assumes content fills the output; retain `.contentRect`, `.contentScale` and `.scaleFactor` metadata rather than silently applying it to padded/scaled content. Apple explains cropping to content and undoing content/display scaling. [sourceRect](https://developer.apple.com/documentation/screencapturekit/scstreamconfiguration/sourcerect), [updateConfiguration](https://developer.apple.com/documentation/screencapturekit/scstream/updateconfiguration(_:completionhandler:)), [frame metadata](https://developer.apple.com/documentation/screencapturekit/scstreamframeinfo), [Apple scaling explanation](https://developer.apple.com/videos/play/wwdc2022/10155/). Local SDK `SCStream.h` also explicitly describes `sourceRect` as points in the display's logical coordinate system.

The current Apple sample requires macOS 15; that does not raise this app's deployment target. SCStream, app exclusion and sourceRect are available before macOS 13. Filter `contentRect`/`pointPixelScale` and SCScreenshotManager require 14. Keep `#available` gates and the existing macOS 13 screenshot fallback; live capture uses SCStream on both versions. [Apple availability metadata](https://developer.apple.com/documentation/screencapturekit/sccontentfilter/pointpixelscale.md), [SCScreenshotManager](https://developer.apple.com/documentation/screencapturekit/scscreenshotmanager), [sample requirements](https://developer.apple.com/documentation/screencapturekit/capturing-screen-content-in-macos).

## Hand gestures

Adapt xynova's `Gesture.parse`, `GestureCatalog`, `ArmView.reloadGestures/setGesture/applyPicture`, `HandMaker.makeGesture/pointingWrist/cuffSpan`, and `CustomHands.addGesture/removeGesture`. Keep base pointing geometry for aim, stick and contact location; only the displayed picture changes. Imported poses match the base wrist and canvas, with width/height caps. Invalidate both pose thumbnails and full/resized-image caches when a pose is replaced/deleted; refresh external file changes too. Sources: [PointerStyle.swift](https://github.com/xynova/tinyhand/blob/c7bbac616dde0decf97f3522445646a390bcdaf7/Sources/TinyHand/PointerStyle.swift), [ArmView.swift](https://github.com/xynova/tinyhand/blob/c7bbac616dde0decf97f3522445646a390bcdaf7/Sources/TinyHand/ArmView.swift), [HandMaker.swift](https://github.com/xynova/tinyhand/blob/c7bbac616dde0decf97f3522445646a390bcdaf7/Sources/TinyHand/HandMaker.swift).

Pose changes must also invalidate local `lastPose`, display-image identity and contact-shadow masks. Derive the shadow silhouette from the displayed pose with the same base transform, or suppress that shadow while a pose is shown; do not retain the pointing-hand shadow. Keep decoded/resized pose caching bounded to the selected hand and outside event-tap callbacks. [Local ArmView/contact shadow](../../Sources/TinyHand/ArmView.swift).

Treat the donor filename suffix as a pose ID, **not an assigned hotkey**. Add optional pose bindings beside the existing presentation bindings; use the same duplicate/reserved/unavailable checks and `Preferences.storage`. Extend `HotKeyCenter.register` with optional release handling, preserving local `kEventHotKeyExclusive`; the donor uses nonexclusive registration. Include command/hand identity in the registration signature, which currently contains only key codes/modifiers. Register only assigned, decodable poses for the enabled selected hand in an eligible context. A missing pose leaves the base hand intact and must not claim readiness. Laser, Spotlight and Presentation pointer have no hand poses. [Local registration](../../Sources/TinyHand/AppDelegate.swift), [local HotKeyCenter](../../Sources/TinyHand/HotKeyCenter.swift), [donor release implementation](https://github.com/xynova/tinyhand/blob/c7bbac616dde0decf97f3522445646a390bcdaf7/Sources/TinyHand/HotKeyCenter.swift), [donor per-hand catalog](https://github.com/xynova/tinyhand/blob/c7bbac616dde0decf97f3522445646a390bcdaf7/Sources/TinyHand/PointerStyle.swift).

Use the donor's ordered held-pose stack so releasing an older key cannot clear a newer pose. Cancel on key or required-modifier release, Escape, shortcut recording, menu/settings/text/capture entry, Interact change, hand/catalog/display change, off and sleep/lock. Clear repeat/held state on cancellation so a fresh press is required. If modifier observation uses InputTap, preserve its existing mouse/Escape pair owners and generation rules; forward unrelated input unchanged. Reuse eligibility from `canUsePresentationShortcuts`, also excluding radial ownership and active drags. [Donor held-key logic](https://github.com/xynova/tinyhand/blob/c7bbac616dde0decf97f3522445646a390bcdaf7/Sources/TinyHand/OverlayController.swift#L579), [local input ownership](../../Sources/TinyHand/InputTap.swift), [local context](../../Sources/TinyHand/OverlayController.swift).

The smallest integration is lossless decode to equivalent PNG filenames, retaining source hashes below. Alternatively change discovery, availability and packaging together. Add a per-hand count/preview to the existing library without resizing the chooser on hover. Display actual assigned shortcuts or Unassigned. ## Tap swing

Adapt tumaranja's small pose calculation, not its input controller. `ArmView.swing(at:)` supplies 0.13-second wind-up, 0.09-second strike and exponential settling with 0.12-second constant. `held.didSet` records release time; `skipSwing()` reaches contact immediately; `tapSoundDelay` is 0.22 seconds for swinging hands. The range is 0...2; donor default is 1. Its `b21dc52...` ArmView/OverlayController content matches the pinned main tip. Sources: [ArmView](https://github.com/tumaranja/tinyhand/blob/b21dc52a6d6646f9608f81bea1e4c271bb1f3cff/Sources/TinyHand/ArmView.swift), [range preference](https://github.com/tumaranja/tinyhand/blob/f9917581f08f2ae0a6789d71b664cfcc575fc84d/Sources/TinyHand/Preferences.swift).

Keep `pointerMotion` follow behavior separate. Add a clamped swing preference and reset entry; preserving current installs with default zero is the least surprising choice. Exclude non-hand presentation styles. Feed the visual pose into existing ArmView/contact shadow, without delaying event delivery, ink creation or Interact forwarding. The local controller calls `ink.begin` on mouse-down, so copying donor `if ink.isDrawing { skipSwing() }` would skip every Draw tap. Detect actual dragging in `dragged(to:)` instead and reach contact immediately there. Schedule at most one contact sound per press with a cancellable token; cancel it on drag-immediate contact, a replacement press, off, context/style/mode change, sound disable and system shutdown. The donor's bare `asyncAfter` can play after cancellation. Sources: [local press/drag/Interact observation](../../Sources/TinyHand/OverlayController.swift), [local motion](../../Sources/TinyHand/PointerMotion.swift), [local shadow](../../Sources/TinyHand/ArmView.swift), [donor delayed sound](https://github.com/tumaranja/tinyhand/blob/f9917581f08f2ae0a6789d71b664cfcc575fc84d/Sources/TinyHand/OverlayController.swift#L73).

Reduce Motion should force swing range zero, immediate sound and immediate pose/loupe transitions, with no zoom-grow, glide or rotating preview. Observe setting changes through `NSWorkspace.notificationCenter`; discard active animation state when it turns on. [Apple Reduce Motion contract](https://developer.apple.com/documentation/appkit/nsworkspace/accessibilitydisplayshouldreducemotion).

## Guided hand import

The local app already has Describe → Make image → Add, file/drop import, validation, preview, naming, persistence and selection. Reuse `MakeHandPage`, `SettingsModel.loadDraft/saveDraft` and `CustomHands.add`. PlayPointer's useful change is explicit handoff guidance: `openChatGPT()` copies the prompt then opens ChatGPT home, explaining paste/send/download/import. Add true alpha transparency, no baked checkerboard, upright single hand, no stick/shadow/cropping guidance; say that Add hand also selects it. A transparent checkerboard preview helps expose opaque backgrounds. Sources: [local page](../../Sources/TinyHand/HandMakerSettings.swift), [local model](../../Sources/TinyHand/SettingsModel.swift), [donor openChatGPT and MakeHandPage](https://github.com/omiusgm/playpointer/blob/6895f5b964f45a49b5f3d85ab7f8997bd149497e/Sources/TinyHand/SettingsView.swift#L103).

Keep the local hand-specific validator and generated stick geometry. PlayPointer relaxes validation for arbitrary objects and changes wrist/render assumptions; that is beyond guidance. Keep a separate pose-import route using xynova's gesture-aware validation, which relaxes only pointing-specific rules. Preserve failed-import feedback and require successful decode/composition before persistence. The current minimum-size check accepts 64 pixels but its error asks for 512; make that guidance consistent. Sources: [local HandMaker.read/check/compose](../../Sources/TinyHand/HandMaker.swift), [donor object validator](https://github.com/omiusgm/playpointer/blob/6895f5b964f45a49b5f3d85ab7f8997bd149497e/Sources/TinyHand/HandMaker.swift), [pose validator](https://github.com/xynova/tinyhand/blob/c7bbac616dde0decf97f3522445646a390bcdaf7/Sources/TinyHand/HandMaker.swift#L177).
