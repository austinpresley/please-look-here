## Remaining upstream differences and judgment

Upstream's existing [URL/state-file automation](https://github.com/nilbuild/tinyhand/blob/da98f98d529971297487b0ec6ef07dc549555686/Sources/TinyHand/Automation.swift) exposes `tinyhand://` actions and writes `state.json`. Local JSON/AppleScript/Stream Deck already cover its main control/readback purposes. Exact URL/state-file compatibility remains absent, but was not selected. Adding another transport would be small-to-medium work with command-validation, identity and stale-state risks; there is no new upstream evidence to prioritize it. Sources: [local protocol](../control-protocol.md), [AppleScript](../../Sources/TinyHand/AppleScriptSupport.swift), [Stream Deck link](../../Sources/LookHerePleaseDeck/AppLink.swift).

The older upstream [double-Shift interaction](https://github.com/nilbuild/tinyhand/commit/519cd5343f17e1f0a7126163444562682f1fa3e3), [Command-arrow drawing](https://github.com/nilbuild/tinyhand/commit/74b139c699d356675e892347d55d0c0baccc44f2), [toolbar option](https://github.com/nilbuild/tinyhand/commit/673003672c7696198a7915fcf1f69d6ecb7fc704) and [menu-icon fix](https://github.com/nilbuild/tinyhand/commit/3d9f5dd169f27ba58816889b0e1ca4300d5ca02d) add no newly missing core capability. Local Interact, explicit Arrow, toolbar policy and current menu controls cover the relevant purposes. Copying fixed gestures would conflict with S-015's user-assigned shortcut decision in [STORIES.md](../STORIES.md).

Recommended upstream integration effort for this run is **none**. Existing runtime uncertainty remains separate from source overlap: the latest [validation record](../VALIDATION.md) still excludes actual lock/sleep, physical mixed-scale displays, Intel/older-macOS runtime and USB Stream Deck acceptance. The earlier audio-recovery evidence uses injected failures rather than live screen sharing. This research did not repeat or upgrade those claims.
