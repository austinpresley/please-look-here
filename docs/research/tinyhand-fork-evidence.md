## Method and preserved evidence

1. Queried the root repository metadata and every page of `/forks?per_page=100&page=N`, following pagination until no next page remained. The root returned 42 records on one page. Queried the same forks endpoint on all 42 discovered forks, recursively. All 42 child lists were empty, all repository `parent` and `source` fields name `nilbuild/tinyhand`, and there were no public fork-of-fork repositories to add. This covers all 43 forks endpoints, rather than trusting a UI page or a default-branch-only search. The API headers and response bodies are preserved.
2. Queried all branch pages on the root and every fork. Each fit on one page, with a maximum of four branches in a fork. Saved every full branch SHA. Used a separate bare git object database in the cache, fetched URLs directly without changing the working checkout's configuration or remotes, and retained audit refs for every head.
3. For each tip, computed `git merge-base`, ahead/behind counts, all commits absent from upstream, the complete branch diff from its merge base, and a second diff directly against latest upstream. All 22 ahead branches have the latest upstream SHA as their merge base and are zero commits behind. Saved the GitHub compare API response for each changed branch. Inspected source diffs and final source, including OS backends, routing, capture, drawing, toolbar, preferences, and packaging. Titles only label the commit ledger below; feature claims come from source.
4. Deduplicated commit objects by SHA and non-merge patches with `git patch-id --stable`. Cross-checked the resulting patches against the entire upstream history. Grouped independently implemented versions of the same user feature below.
5. Independently reran `git ls-remote --heads` for all 43 repositories after the source review. All 57 upstream-plus-fork head name/SHA pairs matched the initial API census. A second root repository/forks API read still returned 42/42/42 and the same repository set. See the saved [verification JSON](/tmp/tinyhand-fork-audit-20261109/verification.json).

The stable cache is `/tmp/tinyhand-fork-audit-20261109`. It contains:

- `census.json`, `upstream.json`, `branches.tsv`, `branch-analysis.json`, and `branch-analysis.tsv` for the complete census and ancestry classification.
- `api/<owner>/<repo>/repo.json`, `forks-1.json`, `branches-1.json`, matching HTTP header files, compare JSON, and git head listings. `requests.jsonl` records initial API request endpoints and timestamps. Compare and final verification requests have their own saved headers and bodies.
- `network.git`, the full fetched commit and blob objects, with `refs/audit/<owner>/<repo>/<branch>` for every observed branch.
- `diffs/<owner>__<repo>__<branch>.diff`, `.text.diff`, `.stat.txt`, `.names.txt`, and `.vs-upstream.diff` for every fork branch. Merge-base diffs are empty for unchanged/behind-only branches; direct upstream diffs show what behind branches lack. Slashes inside branch names are encoded as `__`. The binary diff retains changed assets; the text diff omits binary payloads for reading.
- `commits/<40-character-sha>.diff` and `.json`, plus `unique-commits.json`, `upstream-commits.txt`, and `upstream-patch-ids.txt`. `snapshots/` contains changed text source blobs at each ahead tip. The bare database has the complete trees, including unchanged and binary files.
- Census, analysis, review-cache, verification, and note-writing scripts, plus `progress.txt`, for a reproducible local handoff.

### 0xdhrv/tinyhand: local automation bridge

One new commit, [`602e3f4ad3c0`](https://github.com/0xdhrv/tinyhand/commit/602e3f4ad3c0436bd06fa7a97b318246e3bdff2a), on `f/native-control-bridge`; `main` is unchanged. [compare](https://github.com/nilbuild/tinyhand/compare/c5fb36b7c4d7c87480958872a724b30a52427a47...602e3f4ad3c0436bd06fa7a97b318246e3bdff2a).

- Adds a bundled-executable `--ctl` JSON client and a running-app Unix-domain-socket server. Operations include status/capabilities, pointer discovery and thumbnails, on/off/toggle, clear, style/laser selection, settings batches, sound toggle, pin/unpin, opening Settings, and opening the existing custom-hand creator. This is an automation integration, not a new hand generator. The CLI requires the compatible app to be running. Sources: [ControlBridge.swift L4-L175](https://github.com/0xdhrv/tinyhand/blob/602e3f4ad3c0436bd06fa7a97b318246e3bdff2a/Sources/TinyHand/ControlBridge.swift#L4-L175), [main.swift L4-L6](https://github.com/0xdhrv/tinyhand/blob/602e3f4ad3c0436bd06fa7a97b318246e3bdff2a/Sources/TinyHand/main.swift#L4-L6).
- Validates allowed operations, fields, booleans, finite numeric ranges, style IDs and loadable assets before applying configuration. Applies a preferences batch with one change notification, preserves the active pointer state for configuration, and returns native post-operation state. Activation checks Accessibility and reports failure without a second overlay. Pinning enforces eight maximum and at least one remaining pointer. Sources: [ControlBridge.swift L27-L156](https://github.com/0xdhrv/tinyhand/blob/602e3f4ad3c0436bd06fa7a97b318246e3bdff2a/Sources/TinyHand/ControlBridge.swift#L27-L156), [Preferences.swift L186-L202](https://github.com/0xdhrv/tinyhand/blob/602e3f4ad3c0436bd06fa7a97b318246e3bdff2a/Sources/TinyHand/Preferences.swift#L186-L202).
- Transport uses a bundle-specific per-user temporary directory with owner/mode checks, mode 0700 directory, mode 0600 socket, `getpeereid` on both sides, exclusive server lock, bounded newline framing, and short I/O deadlines. UI actions dispatch to the main thread. Adds a `TinyHandControlVersion` Info.plist marker and a local handler/socket test harness, plus a hosted-workflow test step. Tests and the workflow were inspected as source and were not run. Sources: [ControlTransport.swift L6-L220](https://github.com/0xdhrv/tinyhand/blob/602e3f4ad3c0436bd06fa7a97b318246e3bdff2a/Sources/TinyHand/ControlTransport.swift#L6-L220), [control-protocol.md](https://github.com/0xdhrv/tinyhand/blob/602e3f4ad3c0436bd06fa7a97b318246e3bdff2a/docs/control-protocol.md).

Integration caveats from source: any process under the same user can control the app; there is no per-client authorization. Lost replies must not lead clients to blindly replay toggle mutations. The main-thread deadline rejects a request that has waited too long to start, but this is not a transactional persistence layer. Keep the local integration and omit hosted workflow changes under Austin's policy.

### sergvax/tinyhand: pointer-only interaction as the default

Feature commit [`a18a86a2719e`](https://github.com/sergvax/tinyhand/commit/a18a86a2719e2fd0d63d49a1e43c8e988a264d98) plus documentation [`05ade042c6d7`](https://github.com/sergvax/tinyhand/commit/05ade042c6d77d534505dbd6c269909d90befd9f); [compare](https://github.com/nilbuild/tinyhand/compare/c5fb36b7c4d7c87480958872a724b30a52427a47...05ade042c6d77d534505dbd6c269909d90befd9f).

Adds persisted `screenDrawingEnabled`, default **false**, exposed in the menu and General settings. With drawing off, the event tap still observes down/up to animate the hand and all events return to the underlying app. The overlay always ignores hit testing, including over the Dock. ## Limits and remaining verification

- This covers current public members of GitHub's nilbuild/tinyhand fork network and all their current public branch heads. It does not claim to enumerate private/deleted forks, deleted or unadvertised branches, tag-only work, detached copies outside the GitHub fork network, unpublished local changes, or unreachable commits. The recursive fork API and final head verification found no additional current public fork-of-fork.
- API reads are not atomic. The initial census and later git verification matched, and the final root listing was unchanged. Full response headers/timestamps allow a later audit to locate any drift. The upstream main SHA, every fork head and compare base remain fixed in this report.
- Static source/diff inspection can establish that code exists and how it is wired. It cannot establish compilation, frame rate, correct click forwarding, permission recovery, release signing, external CLI behavior, screenshot pixel correctness, or actual multi-display behavior. Existing test files and README benchmark claims are not treated as executed evidence. No binaries, build scripts, test harnesses, workflows, release commands or third-party agent CLIs were executed.
- Asset diffs and references were inventoried. This audit did not visually validate every image, prove original artwork provenance, or review redistribution rights beyond the repository files.
- Large forks change names, preferences, defaults, update feeds, signing identities, release scripts and hosted workflows alongside app code. Those changes are not necessary to adopt an isolated feature. The evidence inventory intentionally records these couplings; the parent report should decide useful scope and rank it independently.
- No app source, git config, remotes or remote state was modified. The only requested repository artifact is this research note. All helper scripts, downloaded API evidence, git objects and diffs are under the specified cache directory.
