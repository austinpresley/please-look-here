## Authorized implementation and later clarification

Austin authorized S-001 through S-004 after the priority review. He replaced
the named Point and Draw modes with a single Interact toggle. On enables native
interaction with the underlying app; off captures drawing input with the same
pointer. This supersedes the earlier two-mode labels. Keep the existing shortcut
and remove the held-modifier interaction.

The implementation UX for the retained visibility option is to hide only during
native mouse presses and drags when disabled, then restore on the last release.
The default remains visible. This timing is an implementation decision, not a
verbatim request.

## Follow-up: pointer defaults and individual customization

Austin now understands that a laser click is an ordinary mouse click while the
app's red dot is selected. He suggested replacing the laser-specific sound
exception with shared pointer defaults and optional customization for individual
pointers. Sound and appearance belong in that model. His examples were a metal
hand and a squishy hand needing different tap sounds. See S-012.

Proposed UX, not yet approved detail: inherit each setting independently, show
an explicit Use Default choice, and let the toolbar speaker mute all pointers
without changing their saved sound choices. The master-mute behavior was the
assistant's recommendation, not Austin's explicit request.

Austin also mentioned optional click animations for particular hands as a
separate exploratory idea. See S-014. This is not required to redesign settings.

## Follow-up: quick controls at the cursor

Austin does not prefer the current floating toolbar as the main control surface.
Keep it available as an option. His preferred direction is a radial menu that
appears at the current cursor position only while a configurable modifier is
held. It should support quick changes during pointing, including pointer,
color, drawing tools or shapes, Interact and suitable existing actions. Pointer
fine-tuning belongs in Settings. See S-013.

- Support multiple levels, such as Color -> a color, Pointer -> a pointer, or
  Shapes -> a shape, reached by movement rather than repeated clicks.
- Make movement fast enough to learn by muscle memory. A timed hover should
  not be required to move through the hierarchy.
- Close on modifier release, item selection or an outside click. Austin did
  not settle whether release itself commits a highlighted action.
- Design for the visible large hand: generous targets, readable choices and
  an understandable selection point. Preserve the app's visual character.
- Explore brief, tactile-looking button feedback. The exact geometry, number
  of directions, animation treatment and modifier key remain open.

Design recommendations to evaluate later: fixed directions, a center area for
cancellation, a small set of favorite pointers, a shallow hierarchy and a menu
that keeps the active fingertip from obscuring labels. Test release-to-select
against release-to-dismiss before deciding. Keep ordinary keyboard and menu
access to the same actions. Opening this menu must not revive the removed
hold-to-Interact behavior or accidentally draw or click through to another app.

These follow-ups record future design direction. They do not authorize
implementing a new menu, new pointer settings or click animations in this pass.
