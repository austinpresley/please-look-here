# Native Quick controls v9 implementation

This is the implementation contract for the native app. ROUND2's merged specification takes priority, followed by frozen prototype-v9 and GRADE-7. Phase A leaves source changes uncommitted for Claude's review. Rendering approval and native release approval remain separate.

## Phase A: model, input, persistence and tests

### Data and files

- `RadialSession.swift` owns a value-type state machine with no windows, native event sampling, timers or preference access. `RadialGeometry` owns the invocation display's usable rectangle, clamped 384 pt panel, 164 pt ring, fixed clockwise axes, and contiguous half-open angular sectors. `RadialItem` separates current state, inspection, eligibility, disabled reason, pending title/subtitle, navigation and validated command payload. `RadialCatalog.swift` builds a frozen eight-root catalog from injected state and pointer entries. History and current-state updates retain identity and order.
- `RadialSession` tracks held/persistent mode, active group, saved parent geometry, real pointer, arming, needNeutral, display eligibility, keyboard focus, focus ownership, matching click press, and terminal state. Entry at 112 pt consumes the whole event and reanchors at that event's pointer. Acquire at 72, retain to 64, neutral at 52; 4 degree hysteresis applies only after inspection acquires a target. Held targets extend to the owned display edge. Persistent targets stop at 164. A clamp shift greater than 8 requires neutral. Returning through Back requires neutral at the parent; returning within 52 of the parent center is allowed only when the two centers are at least 104 apart. No cursor warp.
- Pointer slots persist as six unique raw IDs in `Preferences.swift`, independent of toolbar pins. Initial saved order is glove, lavender, coral, plush, robot, laser, corresponding to N/NE/E/SE/SW/W. Missing and disabled IDs stay in place. Assignment swaps an already occupied identity. Reset removes the saved slots. `PresentationArchive.swift` captures/restores slots in presets and portable backups, validates exact count/IDs/uniqueness, and accepts old version-1 setups without the field by supplying defaults. New exports include the field; older readers will reject those exports through their existing strict schema.
- `RadialInput.swift` retains the existing single InputTap, session IDs, stale timer guards, sampled-release reconciliation and independent key/button pair draining. Pending key, chord, additional modifier, pointer press, scroll, explicit pointer cancellation, system suspension or eligibility loss cancels opening. Recognized unmodified navigation keys can transfer focus after opening; modified chords pass unchanged. The invocation modifier is removed only when classifying held navigation keys. Persistent open/down/up/drag/key events are available before UI wiring. Existing ownership wins over a new open command.
- `RadialMenu.swift` remains a temporary button canvas adapter. It uses the new catalog, active center and sector angles, commits through the validated bridge, and follows reanchoring. All pointers temporarily opens existing Settings through that bridge until Phase C provides the browser. The small-display list and persistent key panel are Phase B, so the adapter refuses undersized displays. The practice fixture and obsolete paging tests migrate to the same thresholds and child ordering.

### Model activation and focus

Pointer movement previews only. Group and Back entries never return commands. Every release, click, keyboard and accessibility activation rechecks enabled state. Disabled items remain inspectable, with no candidate and no fill. Keyboard order starts north at root and immediately clockwise after Back in a child, ending with Back. Tab/Shift-Tab and Right/Left cycle, 1 through 8 address root only, Return/Space activate, held Escape cancels the entire session, persistent Escape/Backspace goes back then closes at root. Held Backspace does nothing. Modified chords do nothing to model selection. Persistent mode owns focus from opening; held keyboard/AX activation transfers it, and subsequent pointer movement removes only the keyboard outline, not ownership. List arrows follow list order.

Matching persistent down/up must have the same target and level. Hub down/up goes Back or dismisses. An outside pair dismisses and executes nothing. Leaving the pressed target during a drag permanently cancels that activation, even if the pointer returns. This tightens the prototype's endpoint comparison to the explicit drag-away cancellation requirement. Held pointer cancellation dismisses; persistent pointer cancellation clears the press.

## Phase B: native rendering, accessibility, list and persistent mode

### Files

`RadialMenu.swift` becomes the panel/controller adapter. New `RadialRenderer.swift`, `RadialAccessibility.swift` and `QuickControlsList.swift` own stable layer rendering, semantic elements and the small-display list. `OverlayController.swift`, `RadialInput.swift` and `InputTap.swift` connect persistent focus and event ownership. `Preferences.swift` stores the new unassigned shortcut; `AppDelegate.swift` and `HotKeyCenter.swift` register the open action and preserve conflict rollback. Phase B can keep the final menu/settings entry wiring for C while exercising the entry through the test bridge. Replace the current close-on-preference-change policy only when state/availability can refresh safely without changing frozen slots.

### Rendering

Replace `RadialCanvas` button reconstruction with one native material host. On macOS 26 use one `NSGlassEffectView`, guarded by availability; on macOS 13 through 25 use one `NSVisualEffectView`. Both contain a layer-backed view with stable base, sector, pending-fill, current-check, keyboard-outline, artwork, label and hub layers per level. Use `CALayer`/`CAShapeLayer` sectors and real `NSImage(systemSymbolName:)` SF Symbols, checking every symbol on macOS 13. Cache level nodes and update properties on hover; never rebuild the tree for pointer movement. One active ring replaces the previous level. Panel 384, visible disc 328, ring 64...164, hub 56, content radius 118. Pointer art 32, preview at most 36, symbols 24, root/child type 13/12, hints at least 11. Labels remain horizontal and wrap to two lines; the neutral origin keeps a 20 by 20 clear reserve.

Use semantic cream/plum colors with opaque #F8F5F1/#29242D fallbacks. Starting selection pairs are light #B6423B/white and dark #FF9589/#302736. Command/tool selection gets a flat fill; pointer/ink gets tint and a 2 pt arc. Current checks and the keyboard focus outline remain independent. Use a contrasting focus halo, readable disabled inspection and reasons, physical-pixel separators, stronger Increase Contrast strokes, and no material with Reduce Transparency. Validate final pixels over bright slides and busy content at 1x/2x.

Opening is 120 ms ease-out, optional 0.98 scale; fill 60 ms, hub 80 ms, child 100 ms, Back/dismiss 80 ms. Reduce Motion removes scale/interpolation, uses 80 ms opening opacity, and makes selection, hub, child and cancellation immediate. Commands do not wait for animation.

### Accessibility, list and persistent panel

Expose stable `NSAccessibilityElement` children with menu/button roles, title, enabled state, selected/current value, disabled explanation, frame and press action. Disabled elements can receive explanatory focus but cannot execute. Focus the semantic menu on persistent open and after held keyboard transfer. Rebuild semantic children only when level/catalog changes; post focused-element and announcement notifications on changes. Preserve focus ownership through pointer movement and child/Back replacement. Test VoiceOver's Control-Option chords without consuming them. Verify Full Keyboard Access and Voice Control.

Introduce a key-capable `NSPanel`, an unassigned `Open Quick controls` shortcut and a menu-bar command, distinct from Hold to open. Save the previous frontmost application/window/responder; activate only when persistent or keyboard ownership needs it, and restore on close if still valid. Held pointer-only invocation stays nonactivating. Persistent groups open on matching mouse-up, Return, Space or AX press, never hover. Keyboard/AX group origin is 112 pt along its fixed axis. Outside click dismisses and drains both halves, with drag-away cancellation. Ensure InputTap-owned pairs do not reach local monitors twice.

If either usable dimension is below 384, use a native scrollable command list with the same catalog, state, activation, Back and focus ownership. Never shrink type/ring. Up/Down and Tab cycle list order. Clamp a list window to the usable display, preserve readable row heights, and keep all commands reachable. Cancel if its owned display disappears or layout changes; do not silently migrate the gesture.

## Phase C: browser, recovery, capture and integration

The file changes are new `PointerBrowser.swift` and `ClearRecovery.swift`; existing `DrawingModel.swift`, `OverlayController.swift`, `ScreenCapture.swift`, `ScreenshotSelection.swift` and `ScreenshotResult.swift` for history/capture coordination; `MenuBarCommands.swift`, `MenuBarControls.swift`, `SettingsModel.swift`, `SettingsView.swift`, `ShortcutNavigation.swift` and `AppDelegate.swift` for wiring; and `ControlBridge.swift`, `docs/control-protocol.md` and `docs/VALIDATION.md` for inspection and verification. Add focused browser/recovery/capture tests alongside the existing radial and input suites.

- Add a separate key-capable pointer browser window and controller. All pointers closes/drains radial before opening. Start at 560 by 600 with native close, focused search, All/Favorites scope, up to seven columns of 64 by 72 cells, 8 gaps, 36 art, wrapped full names, current check, neutral hover and separate focus outline. Adapt columns and scroll on small displays. Empty results clear the provisional selection and Return does nothing. Arrows navigate by actual columns; Return selects/closes, Escape cancels/restores focus. Do not create a third radial level.
- Favorite editing has a separate candidate and six labeled destination rows with Use controls. Candidate cell click/Return never changes the live pointer. Use assigns or swaps, persists through Preferences, announces the destination and focuses that row. Search Return retains editing semantics. Escape, Done and the footer action all leave editing consistently, restore the Edit button focus/label, and remove the selected-candidate grammar. Constrain the editor body vertically; at 320 by 180 all row buttons must remain reachable without horizontal scrolling.
- Add a Clear recovery controller around `AnnotationDocument.clear()` and history revision identity. A Clear creates one existing full-document undo checkpoint, closes radial and shows `Drawing cleared` with Undo and Dismiss. Recovery remains until dismissal or the next document edit/undo/redo; stale buttons cannot undo an unrelated later edit. Add app-owned Command-Z/Shift-Command-Z routing while the app owns the recovery/control focus, using the same annotation undo/redo methods. Never hijack another application's normal document shortcuts. Closing a focused snackbar restores the prior owned responder. Keep normal undo available after recovery dismissal.
- Coordinate `OverlayController`, capture code, radial, browser, arm cue, previous success/error feedback and snackbar. Screenshot closes controls immediately, clears feedback, hides recovery temporarily, and waits for window removal from the capture scene before capture. Use exclusion window IDs where capture APIs support it. Restore valid recovery after capture; if history changes during capture, leave it expired. Never show pre-capture success. Report saved/copied outcome or a persistent actionable error after completion. Preserve all existing capture exclusion and input protections.
- Wire menu-bar/settings shortcut labels and current states, new browser and open action. Refresh toggle requests/current flags from actual app state without moving slots. Use the validated control bridge for every app command; browser/Back are internal navigation. No direct preference changes in the renderer.
- Extend `ControlBridge.swift` and `docs/control-protocol.md` through the existing gated validated endpoint. Proposed commands: persistent `radial-open`, model-only `radial-key`, `radial-press`/`radial-release`/`radial-cancel`, browser open/search/focus/edit/assign/close, recovery undo/dismiss and app-window snapshot/appearance/accommodation overrides. Validate schema, finite points, IDs, mode, session ID and absolute snapshot paths. Do not add native-input posting. Status includes mode/level/origins/display/armed/needNeutral/outside, inspected and eligible IDs, focus ownership/keyboard state, current/disabled reasons, favorites, browser candidate/editor/focus, recovery revision and excluded windows. Keep the existing protocol version unless compatibility requires a documented bump.
